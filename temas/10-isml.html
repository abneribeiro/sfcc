Templates ISML

ISML (Internet Store Markup Language) é a linguagem de templates do B2C Commerce: HTML com tags <is…> e expressões ${…}. No SFRA, o template só apresenta: recebe o pdict montado pelo controller e o transforma em HTML, sem lógica de negócio. Este tema cobre todas as tags que você vai usar e as que caem na prova, como reaproveitar código com includes, decorators e custom tags, como evitar XSS com encoding, e como o cache de página se declara no template ou no controller.

Conceitos e glossário

Template
Arquivo .isml em cartridge/templates/<default|locale>/…. Nunca direto em templates/: sempre numa subpasta de locale.
pdict
O "pipeline dictionary": os dados disponíveis ao template. No SFRA é o viewData passado em res.render(template, data).
Expressão
${…}: JavaScript avaliado no servidor, inline ou em atributos de tags.
Local include
<isinclude template="…"/>: processa outro template no mesmo request, com o mesmo pdict.
Remote include
<isinclude url="…"/>: outro request a um controller, com cache próprio, montado pelo Web Adapter.
Decorator
Template-moldura (<isdecorate> + <isreplace/>) que envolve o conteúdo da página.
Custom tag
Tag própria declarada com <ismodule> e implementada por outro template.
Encoding
Conversão de caracteres especiais (< → &lt;) para impedir XSS. É o padrão em <isprint>.

Pela documentação, as tags e os nomes de atributos não diferenciam maiúsculas de minúsculas, mas os valores dos atributos sim; a recomendação é escrever tudo em minúsculas. Na primeira execução, o template é convertido numa estrutura interna; depois, o processador avalia tags e expressões e envia HTML estático ao navegador.

Expressões e variáveis disponíveis

Variáveis de topo disponíveis nos scriptlets e nas expressões: pdict, request, session, customer e out (o PrintWriter da página).

Dois cuidados da documentação: </body> é palavra protegida em ISML e não pode aparecer em comentários nem em JavaScript do template (ofusque com "</bo" + "dy>"); e o # é reservado, o que afeta seletores jQuery inline (use [id='x']).

Fluxo: isif, isloop, isset, isremove

Condicionais

Loops

<isloop> aceita items (preferido) ou iterator; var (preferido) ou alias; e status, begin, end (inclusivo) e step. O objeto de status tem count (a partir de 1), index, first, last, odd e even.

Variáveis: isset e escopos

EscopoVisível emDura
pageNo template atual (e nos seus includes locais)Durante a renderização
requestEm todo o request interno (outros templates do mesmo request)O request
sessionEm todos os requests da sessãoA sessão

Se o atributo scope for omitido, o escopo é session. É um erro clássico: uma variável "temporária" acaba persistindo na sessão do comprador. Sempre declare scope="page". O escopo pdict está depreciado; use request.

O guia do SFRA restringe o uso: "isset: only used to set a variable used by isinclude. Don't use complex expressions in the isset." Contas e lógica vão no model.

Encoding e XSS

<isprint> codifica por padrão (encoding="on"). Para contextos que não são HTML comum, há encoders de contexto, mapeados para a classe SecureEncoder:

Contexto do dadoencoding=
Texto no corpo do HTMLhtmlcontent
Atributo HTML entre aspas duplas / simples / sem aspashtmldoublequote / htmlsinglequote / htmlunquote
String JavaScript num bloco <script>jsblock
JavaScript dentro de atributo (onclick)jsattribute
Valor dentro de JSONjsonvalue
Parte de URLuricomponent / uristrict
XMLxmlcontent, xmldoublequote, xmlsinglequote, xmlcomment

Armadilha documentada: ${…} é codificado automaticamente quando o template tem <iscontent type="text/html">. Num template incluído sem <iscontent>, o tipo assumido é text/plain e não há encoding HTML, o que abre espaço para XSS. A documentação recomenda definir o content type ou usar <isprint value="${…}"/> para dados não confiáveis.

iscontent

Define o tipo MIME, o charset, o encoding e o compact (remoção de espaços) da saída. Deve ser a primeira tag do template. O padrão é text/html, UTF-8. O compact não se propaga para includes: cada template que precisa dele declara o seu.

iscomponent

Funciona como um remote include, mas declara a rota e os parâmetros como atributos. Também tem cache próprio e não aceita SEO URLs.

isdecorate e isreplace

O template de conteúdo envolve-se em <isdecorate template="…">; o template decorador marca com <isreplace/> onde o conteúdo entra. Decorators podem ser aninhados. Se o decorador não tiver <isreplace/>, o conteúdo some; se tiver vários, o conteúdo aparece em cada um. O SFRA tem só dois decoradores de página: common/layout/page.isml (com navegação) e common/layout/checkout.isml (sem navegação, o que, segundo a documentação, ajuda a reduzir o abandono no checkout).

O <isslot> está no tema 11.

Custom tags com ismodule

Uma custom tag é um template incluído que recebe atributos. Declaração: <ismodule template="…" name="nome" attribute="a" attribute="b"/>. Uso: <isnome a="…"/> (o prefixo is é acrescentado). A declaração precisa vir antes do primeiro uso; se a mesma tag for declarada várias vezes, vale a última. Os atributos são sempre opcionais e chegam como variáveis com o mesmo nome (em minúsculas) no template da tag.

O SFRA usa custom tags principalmente para content assets: components/modules.isml declara <iscontentasset aid="…"/>, e o page.isml inclui esse arquivo no topo.

Criando uma tag: selo de desconto

O guia de customização do SFRA recomenda ismodule para content assets. Para componentes reutilizáveis em geral, um <isinclude template> com <isset scope="page"> é o padrão mais usado no base. As duas formas funcionam; a prova costuma cobrar a sintaxe do ismodule (o nome sem o prefixo is).

Cache, cookies, redirect e status

iscache

  • type ou varyby é obrigatório; sem nenhum dos dois, exceção.
  • status="off" está depreciado: para não cachear, omita o <iscache>, ou use if para desligar o cache por condição.
  • Com vários <iscache> (inclusive em includes locais), vence o mais restritivo (sem cache, ou o menor tempo). Se qualquer um tiver varyby, a página inteira é personalizada.
  • varyby="price_promotion" cria variações por conjunto de promoções, sorting rules, price books e grupos de A/B test. Use só quando a página realmente varia, porque fragmenta o cache.
  • Se um <isscript> lançar exceção (ou houver erro de banco), o cache da página é limitado a 5 minutos.
  • O <iscache> só tem efeito com o page cache ligado no BM.

No SFRA, o cache se define no controller, com os middlewares de scripts/middleware/cache.js (eles chamam response.setExpires e setVaryBy). A documentação de Content Cache diz explicitamente: "For SFRA implementations, use middleware for caching configuration."

iscookie, isredirect, isstatus

Existem (<iscookie name value maxAge secure…/>, <isredirect location permanent/>, <isstatus value="404"/>), mas o guia do SFRA recomenda fazer o equivalente no controller (res.redirect, res.setStatusCode, cookies via response.addHttpCookie). Template não decide fluxo.

isscript e as regras do SFRA para tags

<isscript> executa JavaScript no servidor dentro do template; vários blocos compartilham o mesmo contexto. É o lugar mais fácil de esconder lógica de negócio na view, e por isso o SFRA o restringe. A lista oficial (Best Practices with ISML, no guia Customize SFRA):

TagUso recomendado no SFRA
iscachePrefira definir no controller
issetSó para variáveis usadas por isinclude; sem expressões complexas
isscriptSó para adicionar JS e CSS de cliente com o módulo assets
ismoduleSó para content assets
iscontent, iscookie, isredirect, isstatusDefina no controller
isobjectEnvolver produtos para analytics e Storefront Toolkit

Chamar ProductMgr, BasketMgr ou um serviço dentro do ISML. Além de misturar camadas, acontece dentro da renderização: um erro ali limita o cache da página a 5 minutos e não pode ser estendido por outros cartridges.

Localização nos templates

O SFRA usa um único conjunto de templates para todos os locales; os textos vêm de resource bundles (templates/resources/*.properties) traduzidos por locale (checkout_pt_BR.properties, checkout_fr.properties…).

  • O terceiro argumento é o texto padrão, usado se a chave não existir.
  • Templates específicos de um locale podem ficar em templates/<locale>/…: a busca tenta a pasta do locale e depois default. Prefira resource bundles a templates duplicados.
  • Datas e valores: <isprint> já formata conforme o locale e o fuso do site.

O tema de localização (locales do site, URLs, fallback, atributos localizáveis) está no tema 14.

Anti-padrões e pegadinhas de prova

<isset> sem scope: a variável vai parar na sessão.

encoding="off" em dado digitado pelo usuário (busca, nome, endereço): XSS.

<iscache> num include local de uma página com dados da sessão: o include afeta o cache da página inteira. Dados da sessão vão em remote include sem cache.

Usar <iscache status="off">: depreciado, gera mensagens no log de deprecação, e depois dele a página não pode reativar o cache. Omita o tag.

  • Remote include = url; local = template. Só o remoto tem cache próprio.
  • Custom tag: <ismodule name="x"> → usa-se <isx>.
  • <isloop>: status tem count (começa em 1) e index; end é inclusivo.
  • Escopo padrão do isset = session.
  • Decorator: <isdecorate template> no conteúdo, <isreplace/> no decorador.
  • <iscomment> é removido da saída; comentários HTML vão ao navegador (não ponha informação sensível neles).

  • isif/iselseif/iselse, isloop com status e isbreak/isnext.

Questões de fixação

  1. Uma página de categoria cacheada por 24h precisa mostrar o nome do comprador logado no header. Como fazer?

    1. <isinclude template="header/user"/>
    2. <isinclude url="${URLUtils.url('Account-Header')}"/>, uma rota sem cache
    3. <iscache status="off"/> na página
    4. <isset scope="session">
    ver resposta

    b. O remote include tem cache próprio; a página continua cacheada e o fragmento pessoal não.

  2. Qual é o escopo de <isset name="x" value="${1}"/>?

    1. page
    2. request
    3. session
    4. pdict
    ver resposta

    c. Sem scope, o padrão é session.

  3. Com <ismodule template="util/badge" name="promobadge" attribute="type"/>, como se usa a tag?

    1. <promobadge type="x"/>
    2. <ispromobadge type="x"/>
    3. <ismodule-promobadge/>
    4. <isinclude module="promobadge"/>
    ver resposta

    b. A tag é declarada sem o prefixo e usada com is.

  4. Como imprimir um termo de busca dentro de um atributo value="…" com segurança?

    1. ${term}
    2. <isprint value="${term}" encoding="htmldoublequote"/>
    3. <isprint value="${term}" encoding="off"/>
    4. <isscript>out.print(term)</isscript>
    ver resposta

    b. O encoder de contexto para atributo entre aspas duplas.

  5. Um template tem <iscache type="relative" hour="24"/> e inclui localmente outro com <iscache type="relative" minute="30"/>. Qual é o cache da página?

    1. 24 horas
    2. 30 minutos
    3. Sem cache
    4. 24h para a página, 30 min para o include
    ver resposta

    b. Includes locais fazem parte da mesma página; vence o mais restritivo.

  6. Num loop, como mostrar a numeração 1, 2, 3…?

    1. ${status.index}
    2. ${status.count}
    3. ${status.position}
    4. ${loop.i}
    ver resposta

    b. count começa em 1; index é o índice na coleção.

  7. Segundo as boas práticas do SFRA, para que serve <isscript> num template?

    1. Buscar produtos
    2. Só adicionar JS e CSS de cliente pelo módulo assets
    3. Calcular impostos
    4. Definir cookies
    ver resposta

    b. Lógica fica em controllers, models e helpers.

  8. Como desligar o cache de uma página hoje, segundo a documentação do <iscache>?

    1. <iscache status="off"/>
    2. Omitir o <iscache> (ou usar if para desligar por condição)
    3. <iscache hour="0"/>
    4. <isstatus value="200"/>
    ver resposta

    b. status="off" está depreciado.
